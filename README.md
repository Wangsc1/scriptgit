# scriptgit

面向 iPhone Scripting 的 Git 客户端：本地文件与空目录管理、真实差异、Stash、提交同步、批量克隆及 GitHub 协作。

## 安装与更新

先安装 [Scripting](https://scriptingapp.github.io/)，再在 iPhone 上打开：

[一键导入 scriptgit](https://scripting.fun/import_scripts?urls=["https%3A%2F%2Fgithub.com%2FWangsc1%2Fscriptgit"])

已安装时，通过 Scripting 对原脚本在线更新，无需删除重装或清除 Token、本机配置与仓库记录。脚本内「设置」用于账号配置，不提供独立的「检查更新」按钮。

手动安装须保留完整仓库目录，脚本目录命名为 `scriptgit`，入口是 `index.tsx`；不要只复制入口文件。iPhone 运行不需要 Node.js。

## 快速开始

1. 在「仓库」页右上角 **＋** 选择「本地仓库」或「克隆仓库」。本地仓库通过系统目录选择器授权访问。
2. **新克隆默认保存到「我的 iPhone / Scripting / git / 仓库名」**，无需启用 iCloud。点「更改目录」可选择 iCloud 或其他父目录，仓库放在所选父目录的 `git` 子目录下。已有 iCloud／外部仓库继续沿用原路径和授权，**不会迁移或删除**。
3. 公开仓库浏览、用户搜索和公开克隆可不配置 Token。访问私有仓库、提交或向 GitHub 写入时，先到「设置」保存并验证 GitHub Token。
4. 进入仓库后，使用 **「文件｜Stash｜状态」** 分段：「文件」管理工作区，「Stash」查看暂存快照，「状态」浏览和搜索提交历史；顶部管理分支、远端、拉取与推送。
5. 编辑文件并返回保存，查看真实差异后，使用「推送」填写提交标题和描述。保存文件本身不会自动提交或上传。

## 首页与目录状态

- 首页打开或从详情返回时，先恢复已有缓存和快照，**不在启动时自动全仓扫描或拉取**。缓存不等于刚完成实时检查；外部工具修改过目录或首次使用新版本时，需要下拉刷新或进入详情读取。
- 首页下拉会依次尝试批量安全快进拉取，再刷新状态。本地不干净、存在未跟踪或忽略文件、合并／变基中、分支分叉或缺少 upstream 等情况会跳过；不会自动合并、提交或覆盖。单仓失败不阻断其他仓库。左滑「拉取」只处理目标仓库。
- 仓库按 GitHub 最近更新时间排序；可配置状态小组件。小组件读取已保存快照，不直接扫描本地工作区。操作结果在 App 内提示，不发送系统通知。
- 摘要区分 Git 文件与目录，例如 **「1 改动 · 4 新增目录」**。目录只计未被可见文件路径涵盖的未跟踪叶目录：多层纯空目录只计叶目录，已有文件的父目录不重复计数；已跟踪目录和忽略路径不误计。
- 「文件」页按真实工作区枚举，空目录、嵌套空目录和纯未跟踪目录在刷新或重进后仍可见。未跟踪目录为绿色「新增」，不靠 `.gitkeep` 等占位文件实现。**Git 本身仍不跟踪空目录**，目录数不会被伪装成可提交文件，也不会单独触发推送或 Stash。
- 枚举不进入 Git 元数据或嵌套仓库，不跟随符号链接。未跟踪的忽略文件／目录不显示；已有跟踪路径不因 ignore 而消失。读取失败或超过安全上限会报错，不能仅凭列表不可见就判断磁盘上没有同名目标。

## 本地文件管理

### 创建与导入

「工作区文件」右侧 **＋** 提供创建文件、创建目录、导入文件、导入目录和导入图片。**目标始终是仓库工作区根目录**，与当前展开哪个文件夹无关。

- 文件名可用任意合法扩展名，也可无扩展名；新文件初始为空，不强制加 `.txt`。
- 文件支持系统选择器多选；照片每批最多 50 张。复制保留选择器导出的文件，不进行文本转码或额外压缩；照片选择器可能提供兼容格式，**不保证取得图库原始 HEIC／RAW**。
- 目录一次选择一个，按原目录名整体导入，包含子目录、空目录和二进制文件。预检发现 `.git`、符号链接、非普通文件或不安全名称时拒绝，不悄悄跳过。
- 不覆盖、不合并同名目标，大小写或 Unicode 等价重名也拒绝。取消不写入；批量文件／照片单项失败后继续，成功项不回滚。失败时核对页面错误和磁盘实际内容，可能已产生的部分目标**不会自动删除**。

### 编辑、预览与移动

点击文件读取的是**当前工作区内容**，不是 HEAD 的旧副本。

- 无损 UTF-8 文本不超过 **512 KiB** 时可编辑，保留 BOM 和换行。二进制、非无损 UTF-8 或超限文件只读。
- 编辑器提供行号、语法高亮、撤销／重做和软换行。有改动时可查看「原内容／改动项」，显示真实增删数量、逐行和行内差异，并适配明暗外观。
- 点「返回」或左边缘右滑会先保存；保存失败或检测到外部修改时留在当前页并保留草稿。「刷新」遇到未保存草稿会先确认。**保存仅写本地工作区，不自动 Stage、提交或推送。** 草稿只在当前会话中保留，强退或系统回收后不保证恢复。
- 本地图片使用可缩放、拖动的图片查看器，不进入文本编辑器。PNG／GIF／WebP／BMP／ICO／JPG／JPEG 在 **≤8 MiB** 时以检查后的原始字节预览；超限明确报错。HEIC／HEIF／TIFF／AVIF／JP2 等交由系统解码并生成最长边目标 1600 的显示缩略图，不保证原图细节或透明保留；解码与手势表现仍需真机确认。预览不修改源文件，无刷新入口，需关闭后重开。
- 长按文件或文件夹可复制、重命名；长按文件还可「移动到…」已有文件夹。文件夹暂不支持移动，列表不提供拖放移动。不覆盖同名目标，遇到符号链接或嵌套 Git 仓库等不安全内容会拒绝。复制失败保留原件及可能的部分副本。
- 正常图标为灰色，新增为绿色，修改／重命名为橙色，删除为红色；图片使用山景图标。重命名提示属于当前文件页会话，不改变 Git 的真实状态；移动后按 Git 展示源路径删除、新路径新增。

## 左滑：删除、暂存、还原、推送

适用按钮视觉上**从左到右**为：**红色「删除」→ 紫色「暂存」→ 橙色「还原」→ 绿色「推送」**，按条件省略并保持相对顺序。首页另有蓝色「拉取」。

| 操作 | 范围与含义 |
| --- | --- |
| 删除 | 文件列表删除本地文件；**删除文件夹会递归删除全部内容，包括未跟踪文件**，必须核对确认。首页「删除」是移除仓库记录及本地 Git 缓存，不删除工作区文件。 |
| 暂存 | 实际是 **Stash**，不是 Git Stage。文件仅保存自身改动，文件夹保存其下改动，首页保存仓库全部改动；保存后所选范围回到 HEAD，无关工作区及索引改动保留，不提交、不推送。 |
| 还原 | 丢弃所选文件改动；首页／文件夹还原还会处理确认范围内的新增空目录。详见下节。 |
| 推送 | **始终提交仓库全部文件改动**，不是只提交左滑选中的文件或文件夹。 |

**Stage 与 Stash 不同：** Stage 把文件变更加入 Git 索引，供下一次提交使用；Stash 把改动保存为可查看、应用的快照。当前详情分段没有独立「改动」页，不要把左滑「暂存」当成 Stage。

### 提交并推送

首页、详情顶部及文件／文件夹左滑「推送」使用同一流程：

1. 有未提交的 Git 文件改动时，弹出**居中的原生输入弹窗**，填写标题和描述。标题必填，默认「更新 N 个文件」；描述可选，取消不写入。
2. 确认后依次执行 **全仓 Stage → commit → pull → push**；有对应远端分支时先拉取，拉取失败或发生冲突便停止，不继续推送。已经成功的本地提交不会因后续网络失败而回滚。
3. 没有文件改动、只有待推送提交时，不再弹提交输入或制造空提交，只同步已有提交。仅新增空目录不会增加推送或 Stash 入口。

### 还原文件与新增空目录

首页仓库和文件夹范围「还原」先新鲜读取，弹出 **「还原文件并删除新增空目录？」**，明确列出文件数、目录数和范围；仅有空目录也可使用。取消零写入，确认后再校验并执行。

- 文件按原有 HEAD／索引还原语义处理，不改变当前分支关联；**单文件还原不顺带清理旁边的空目录**。
- 目录从叶到父处理，不越过选定范围。确认数包含链上实际计划删除的目录，以及仅含本次待还原文件、预计还原后为空的目录，因此可能多于首页只计叶目录的摘要。
- 只删除再次检查确实为空的未跟踪目录。根目录、元数据、已跟踪目录、忽略目录、含隐藏／忽略内容的目录和符号链接保留。确认后新增或发生变化的目录不扩大删除范围；执行中变为非空则保留并反馈。
- 安全删除使用 Scripting **`Python.run`** 调用原子非递归 `os.rmdir`，并检查文件描述符操作、`O_NOFOLLOW` 等能力；**不会用递归删除降级代替**。当前 Scripting 缺少所需能力时，会在文件写入前拒绝此范围还原并提示更新。嵌入 Python 的实际能力及原生确认界面仍需真机验收。
- 途中失败可能已有部分文件／目录处理完成；页面会按真实状态刷新，不伪造「无改动」。不会在启动、拉取或推送时自动清空目录。

### Stash 使用限制

「Stash」分段可保存、查看、应用和删除快照，保存包含已暂存、未暂存及所选范围的未跟踪文件。纯空目录不是 Git 文件，不单独保存为 Stash。

- 首次提交前不能保存；所选范围包含可执行文件、符号链接、子模块或文件／目录类型切换时拒绝，不擅自扩大到全仓处理。
- 应用本工具创建的 Stash 要求工作区／索引干净，且 HEAD 仍为保存时基线。基线改变时，请切回原提交，或用原生 Git 合并应用，避免覆盖新提交。
- 删除 Stash 不可撤销，请先查看内容。

## 分支、历史与 GitHub

- 顶部可切换、创建、重命名或删除分支，管理远端、对比与处理合并冲突。已发布分支重命名会推送新分支并删除远端旧分支，失败会区分本地与远端结果。分支读取失败时先刷新核对，不猜测 `main`／`master`。
- 「状态」分段浏览、搜索提交历史，按条件提供撤销、回退和重编；重编只允许未推送的 HEAD。涉及回滚或强制推送时仔细核对确认范围。
- 提交／Stash 详情提供 **「更改｜文件」**：查看相对第一个父提交的逐文件差异及文件树。更改每批加载 20 个文件，预览每文件最多 300 行；二进制和超限情况会提示。
- 「最近拉取」显示当前分支最近一次成功拉取时间，失败、取消或跳过不更新时间。
- 批量克隆按用户名搜索并分页加载仓库，逐个处理。已克隆仓库默认不勾选，同名文件／目录／符号链接不覆盖、不合并；取消可能需等待当前请求结束，已完成项保留。临时克隆成功后才移动并注册，注册失败会保留下载内容。
- 已识别 GitHub 远端时，详情顶部「GitHub」菜单可进入 **Issues、Pull Requests、Actions、Edit Remote Files**。

**Edit Remote Files** 无需克隆即可通过 GitHub Contents API 编辑现有普通 UTF-8 文件（≤512 KiB）。二进制、符号链接、子模块和 API 未提供内容的文件只读，每目录最多展示 API 返回的 1000 项。保存携带加载时的 SHA，远端变化时拒绝过期保存；失败保留草稿，超时后应先核对远端实际结果。受保护分支、组织策略或权限可能阻止提交，不会自动建分支或 PR 绕过限制。远端提交不修改本地工作区，需要时再拉取。

## GitHub 账号、权限与隐私

在「设置」保存并验证 Token。公开读取可匿名，但 GitHub API 和用户搜索有限流；已配置的 Token 失效时需更新或主动清除，不会悄悄忽略认证失败、降级成公开结果。搜索结果是 GitHub 用户，不是已关联账号列表；认证不保证能列出目标用户的全部私有仓库。

推荐只授权必要仓库的 **Fine-grained personal access token**：

| 场景 | 权限 |
| --- | --- |
| 私有仓库读取、克隆、文件浏览 | Contents: Read-only |
| 文件保存、提交与推送 | Contents: Read and write |
| 修改 `.github/workflows/` | 可能还需 Workflows: Read and write |
| Issues、Pull Requests、Actions | 按实际操作授予对应读写权限 |

组织仓库可能还需审批或 SSO。Classic PAT 的公开仓库写入通常需 `public_repo`，私有仓库需 `repo`，修改工作流另需 `workflow`。

- Token 保存在系统 **Keychain**，不要写进代码、仓库、截图或提交消息。
- 本地新提交作者取自已验证 Token 的 **GitHub 用户名**，邮箱使用 `账号ID+用户名@users.noreply.github.com`，不要求填写或读取私人邮箱。未配置账号时仍可浏览公开内容，但创建本地提交会要求配置账号。
- noreply 地址保护私人邮箱，**不会隐藏 GitHub 用户名**。更换／清除 Token 会使原账号验证缓存失效，不改写旧提交。远端 API 提交作者由 GitHub 按认证账号确定。
- 文件访问限于授权工作区，拒绝路径穿越、符号链接和 `.git` 等危险目标；Git 元数据可能独立存储在 App Group，不应手动当作普通目录清理。请勿同时使用其他 Git 客户端写同一仓库，应用内协调锁不等于跨进程锁。

## 遇到问题

先在测试仓库确认操作范围；重要文件和草稿自行备份。

- 克隆／同步失败：保留完整错误，区分认证、网络、限流和目录授权，不要先删除仓库数据。
- 文件保存冲突：先复制重要草稿，再刷新、比较并修改，不强行覆盖外部更新。
- 目录同名但列表不可见：可能有忽略内容或残留目标，按错误中的名称／类型核对，不自动覆盖或删除。
- 安全空目录还原能力不足：更新 Scripting 后重试，不改用递归清理规避检查。
- 系统选择器、iCloud、图片解码、键盘和手势需以真机表现为准。设置中的性能记录只保留本次运行的慢操作，分享排查信息前检查路径等隐私。
