# scriptgit

在 iPhone 的 [Scripting](https://scriptingapp.github.io/) 中管理本地 Git 仓库：浏览与编辑文件、查看真实差异、暂存与提交、拉取与推送，并使用 GitHub 仓库、Issues、Pull Requests 和 Actions 功能。

## 安装与更新

安装 Scripting 后，在 iPhone 上打开以下链接：

[一键导入 scriptgit](https://scripting.fun/import_scripts?urls=["https%3A%2F%2Fgithub.com%2FWangsc1%2Fscriptgit"])

已安装时在原脚本中使用在线更新，保留本机配置与仓库记录，不必删除重装。也可完整导入仓库文件，脚本目录命名为 `scriptgit`，入口为 `index.tsx`；请保留 `vendor`、`services` 等子目录，不要只复制入口文件。

## 主要功能

- **本地仓库**：添加已有目录、初始化仓库，查看分支、工作区状态、文件树、差异和提交历史。
- **单个与批量克隆**：输入 GitHub 用户名，搜索并分页加载其拥有且当前凭据可访问的仓库，选择后依次克隆；已克隆仓库默认不勾选。
- **本地文件操作**：文本编辑、图片预览、文件及文件夹复制和重命名，以及确认后删除文件或文件夹。
- **Git 操作**：分支管理、暂存、提交、推送、拉取、远端管理、Stash、冲突处理、回滚与提交对比。
- **GitHub**：浏览和操作 Issues、Pull Requests、Actions；无需克隆即可编辑远端现有文本文件并提交。
- **状态展示**：主页仓库按 GitHub 最近更新时间排序，后台刷新状态，提供状态小组件和同步通知。

## 快速开始

1. 在仓库页右上角「+」选择「本地仓库」或「克隆仓库」。
2. 克隆默认保存到 **iCloud Drive/Scripting/git/<repo>**；也可选择其他父目录并授权访问。iCloud 不可用时会报错，不会偷偷改存本地。
3. 公开用户搜索、公开仓库加载和克隆无需 Token。访问私有仓库或向 GitHub 写入时，在「设置」中配置并验证 GitHub Token。
4. 本地提交作者自动使用已验证 Token 对应的 GitHub 用户名，无需另外填写姓名或邮箱。
5. 本地文件保存后，到「改动」页检查差异，再手动暂存、提交和推送。

## GitHub 账号与提交作者

只需在「设置」配置并验证 GitHub Token。

- 本地新提交的作者名称默认使用该 Token 对应的 **GitHub 用户名**，而非显示昵称。
- 推送仍由 Token 认证；填写用户名本身不能获得仓库权限。
- Git 提交格式需要邮箱字段，程序自动生成该账号的 GitHub noreply 地址（`账号ID+用户名@users.noreply.github.com`）。**不需要填写或公开私人邮箱**，也不会读取 GitHub 私人邮箱。
- 未配置 Token 时仍可浏览、克隆公开仓库；创建本地提交或其他需要作者的操作会提示配置账号。旧账号缓存缺少 ID 时会自动向 GitHub 核实，认证或网络失败不猜测身份。
- 更换或清除 Token 会使原账号验证缓存失效。旧手工身份设置不再用于新提交，不改写已有提交历史。
- 无需克隆的「Edit Remote Files」通过 GitHub Contents API 提交，作者由 GitHub 按认证账号确定。

noreply 地址也是提交历史的一部分；它保护私人邮箱，不隐藏 GitHub 用户名。

## 本地文件与差异

在仓库详情的「文件」页展开目录、点击文件，读取的是**当前工作区内容**，不是 HEAD 中的旧版本。

- 无损 UTF-8 文本不超过 **512 KiB** 时可编辑，保留原有 BOM 和换行；二进制、非无损 UTF-8 与超限文件只读。
- 编辑页显示行号、语法高亮，支持撤销、重做和软换行。「返回」或左边缘右滑会先保存；保存失败或检测到外部变更时留在当前页并保留草稿。
- 「刷新」重新加载文件，存在未保存草稿时会先确认。保存只写本地工作区，**不自动暂存、提交或推送**。
- 文件内容修改时，列表前导文件图标显示橙色。本页执行文件重命名后，新目标显示橙色图标与「已重命名」，优先于其它改动标签；这是当前文件页会话提示，不改变 Git 状态，提交或恢复至正常后清除，离开文件页重开不保留。
- 文件存在改动时，可切换「原内容／改动项」。真实增删数量显示在「改动项」上方；删除行标红、新增行标绿，行内变化进一步高亮。
- 日间白底、夜间深灰底，差异正文与红绿高亮同步适配明暗外观。
- PNG、JPEG、GIF、WebP、BMP、ICO 图片支持预览（最多 **8 MiB**），默认按比例限制在安全区域宽度的 80%、高度的 60% 内，小图不强制放大。可缩放；未缩放时可点击、下拉或左边缘右滑关闭，缩放平移和多指操作不触发返回。
- 长按文件或文件夹可复制或重命名；文件夹操作包含全部子目录内容，保留原始字节，不覆盖已有同名目标。仅修改本地工作区，不自动暂存、提交或推送；遇到符号链接或嵌套 Git 仓库等不安全内容将拒绝操作。复制中途失败时保留原件与可能已复制的部分，核对后再处理，不自动清理。文件和文件夹可在确认后删除；**删除文件夹会递归删除其内容，包括未跟踪文件**，请仔细核对范围。
- 文件读写限制在授权工作区，拒绝路径穿越、符号链接、`.git` 和仓库根目录等危险目标。保存前核对加载基线，不静默覆盖外部修改。

草稿只在当前运行会话中保留。强制退出、停止脚本或系统回收后不能保证恢复，请先保存或复制重要内容。

## 克隆与同步

批量克隆会完整分页加载目标用户的可访问仓库。未配置 Token 时只读取公开仓库；配置 Token 后沿用认证，权限不足或认证失败会明确报错，不会悄悄降级为公开列表。

- 用户搜索是 GitHub 公开用户搜索，不是关联账号列表；结果过多时请细化关键词。
- 已有同名文件、文件夹或符号链接会安全跳过，不覆盖、不合并，也不自动改名。
- 各项分别报告成功、失败、跳过或取消；单项失败继续下一项。取消可能需要等待当前请求结束，已完成项目保留。
- 克隆先写入本次临时目录，成功后再移动并注册；失败处理不会删除既有目标。下载后注册失败会保留文件并提示。
- 外部目录通过系统目录选择器授权；默认 iCloud 目录使用 Scripting 自有容器，不猜测系统路径。

每次脚本启动，在首屏显示后后台串行检查一次符合条件的仓库并尝试**安全快进拉取**。本地不干净、存在未跟踪或忽略文件、合并／变基中、分支分叉或缺少 upstream 等情况会跳过，不自动合并、提交或覆盖。单仓失败继续下一仓，原因写入日志；手动拉取入口仍可使用。

主页先显示已保存仓库，后台再更新状态。缓存和上次快照不代表刚完成实时检查；慢读取不会因为界面超时就释放读写锁，也不会把尚未执行的写入偷偷排到后台。

详情页「更改分支」用于选择分支；「重命名」修改当前分支；已发布的分支会同步远端（推送新分支并删除远端旧分支），同步失败会说明本地已完成及远端失败阶段。「状态」页签保留提交历史浏览功能。「最近拉取」显示该仓库各分支最近一次成功拉取时间（含手动及启动自动拉取）；失败、取消、跳过不更新时间，未记录时显示「尚未拉取」。

## GitHub 远端文件编辑（Edit Remote Files）

从已有 GitHub 远端的仓库详情中进入「GitHub → Edit Remote Files」，选择仓库、分支和目录，打开文件、编辑并填写提交消息，点击「提交保存」。

- 通过 Contents API 编辑**现有普通 UTF-8 文件**，上限 **512 KiB**；二进制、符号链接、子模块和 API 未提供内容的文件只读。每个目录最多显示 API 返回的 1000 项。
- 保存携带加载时的文件 SHA，远端发生变化时拒绝过期保存，不自动重试覆盖。失败保留当前草稿；请求超时后请先核对远端实际结果。
- 受保护分支、仓库权限或组织策略可能阻止提交；不会自动创建分支或 PR 绕过限制。
- 远端提交不修改本地工作区，需要时再拉取。关闭前若有未保存修改会提示确认。

## Token 权限与安全

公开读取可不配置 Token，但匿名 API 和用户搜索有限流。已配置的 Token 失效时，请更新或主动清除；程序不会自动忽略认证失败。

推荐使用只授权必要仓库的 **Fine-grained personal access token**：

| 场景 | 权限 |
| --- | --- |
| 私有仓库读取、克隆、文件浏览 | Contents: Read-only |
| 文件保存、提交与推送 | Contents: Read and write |
| 修改 `.github/workflows/` | 可能还需 Workflows: Read and write |
| Issues、Pull Requests、Actions | 按实际操作授予对应读写权限 |

组织仓库可能另需审批或 SSO 授权。Classic PAT 的公开仓库写入通常需要 `public_repo`，私有仓库需要 `repo`，修改工作流还需 `workflow`。

Token 使用系统 Keychain 保存，不要将其写入代码、仓库、README 或提交消息。本地提交作者自动取自已验证的 GitHub 账号。

## 问题排查

- 克隆或同步失败：保留仓库名和完整错误，先区分认证、网络、限流与目录权限，不要直接删除仓库数据。
- 文件保存冲突：先复制重要草稿，再重新加载、比较并修改，不要强行覆盖他人更新。
- 无法打开脚本：说明是 Scripting 启动阶段转圈，还是已进入仓库页。若目录里出现 `文件名 2.tsx`、`文件名 3.ts` 等非预期编号副本，先备份并核实引用，不要直接批量删除或重装。
- iCloud 授权、键盘输入、原生全屏布局和手势需在实际设备确认，建议先使用测试仓库。

## 开发与验证

iPhone 运行无需安装 Node.js。开发测试使用 Node.js、TypeScript；本地编辑器控制器测试另需 esbuild，浏览器测试使用 Python Playwright。

```sh
npm install --prefix /tmp/scriptgit-test-tools typescript esbuild
export NODE_PATH=/tmp/scriptgit-test-tools/node_modules
node --test tests/editorChanges.test.cjs tests/localCodeEditor.test.cjs tests/localFiles.test.cjs tests/localPresentation.test.cjs
```

离线浏览器回归入口为 `tests/localCodeEditor.browser.py`，需先准备 Playwright 及 Chromium。测试使用 mock 服务和一次性测试仓库，不替代真实 iPhone、iCloud 和 GitHub 权限验证。编辑器第三方许可证见 `vendor/local-code-editor-LICENSES.txt`。
